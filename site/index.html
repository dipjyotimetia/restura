Frequently asked questions

Is Restura a free alternative to Postman?

Yes. Restura is free and MIT-licensed, with no account and no paid tier. It imports Postman v2.x and v3 collections, and Postman-style pm.* pre-request and test scripts run in its sandbox.

Do I need to create an account?

No. Open the web app or install the desktop app and start sending requests. There is no sign-up and no cloud sync.

Where is my data stored?

On your device. The web app keeps collections, history and environments in your browser’s IndexedDB; the desktop app stores secrets in your OS keychain; a self-hosted install keeps everything on your server. The only thing that can leave is opt-out crash reports, which exclude request content.

Which protocols does Restura support?

HTTP/REST, GraphQL, gRPC, WebSocket, Socket.IO, Server-Sent Events and MCP in the browser and on desktop. Kafka and MQTT need the desktop app, which also adds client and bidirectional gRPC streaming, mTLS, custom CAs and SOCKS proxies.

Can I run collections in CI?

Yes. The restura-cli package runs collections from the command line with JUnit, HTML and JSON reporters, for example npx restura-cli run ./my-collection.

Can I self-host Restura?

Yes. A single Docker container serves the same web app and its request proxy, so you can run it on infrastructure you control.

How does Restura compare with Hoppscotch and Insomnia?

Hoppscotch is a fast open-source web client with real-time team collaboration; Insomnia is strong for design-first OpenAPI work. Restura focuses on protocol breadth (including Kafka, MQTT and MCP), local-only data and the same app on web, desktop and Docker. It does not offer real-time collaboration or hosted mock servers.

Does Restura work with AI agents and MCP?

Yes. Restura is an MCP client: connect to any Model Context Protocol server to inspect its tools, resources and messages. The desktop app adds an AI assistant that uses your own API key and redacts secrets in headers and bodies before anything reaches the model.
