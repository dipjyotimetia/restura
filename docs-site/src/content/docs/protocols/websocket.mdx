Restura's WebSocket client gives you a full session viewer: every frame sent and received, with timestamps, payload type, and a search bar over the transcript.

## What works

- **Connect** to `ws://` and `wss://` URLs.
- **`{{variables}}` in the URL** — autocompleted and highlighted (unresolved names are flagged). Resolved from the active environment and globals at connect time.
- **Subprotocols + handshake headers** — editable while disconnected (e.g. a `Sec-WebSocket-Protocol` such as `graphql-transport-ws`); the negotiated subprotocol and `Sec-WebSocket-Extensions` (e.g. `permessage-deflate`) are shown in the stats row and the "Connected" transcript entry after the upgrade.
- **Header table** — bulk edit (one `key: value` per line, `//` to disable a row) and an optional description per row. Handshake header values are sent exactly as typed (no `{{variable}}` resolution).
- **Custom headers** during the upgrade — desktop only (sent natively via the main process); the browser `WebSocket` API can't set upgrade headers.
- **Send text frames** with the editor; auto-detects JSON for pretty printing.
- **Send binary frames** — paste space-separated hex bytes (e.g. `48 65 6c 6c 6f`); each token must be whole bytes, and invalid hex is rejected without sending anything. Bytes go out unmodified on web and desktop.
- **`{{variables}}` in messages** — text, JSON and hex frames are resolved at send time with the same scopes as HTTP (globals, active environment, collection and folder variables, plus `{{$dynamic}}` helpers); hex is resolved *before* the bytes are parsed. Unresolved names are sent literally and flagged with a system message in the transcript. Values of variables marked secret are masked (`••••••`) in the transcript; desktop keychain-handle secrets are never resolved in the renderer, so they are reported as unresolved.
- **Saved messages** — click **Saved** in the composer to keep named messages per connection (body + `text` / `json` / `hex` format). Save the current composer, rename, reorder, delete; click a saved message to load it, or use its send button / <kbd>Shift</kbd>+<kbd>Enter</kbd> to send it directly. Saved messages are stored as typed — variables are resolved only when sent.
- **Frame assertions** — the flask button in the message log opens an optional script that runs in the QuickJS [script sandbox](/guides/scripts/) for every frame *received* after it is enabled. The frame is bound as the test-script response (`pm.response.text()` / `pm.response.json()`), so `pm.test` and `pm.expect` work as in HTTP test scripts. Each frame gets a pass/fail badge in the transcript; select it to see per-test results. The script and its enabled state are saved with the connection.
- **Auto-reconnect** — backoff with jitter, configurable per session.
- **Resizable options pane** — with **Options** open, subprotocols and handshake headers get their own pane above the message log; drag the divider (or focus it and use the arrow keys) to resize. The position is remembered.
- **Auth on connect** — Bearer, Basic, API Key, OAuth 2.0, carried as upgrade headers on desktop.
- **Custom close code + reason** — the chevron next to **Disconnect** sends a close frame with your own status code (`1000` or an application code `3000`-`4999`, per RFC 6455) and an optional reason of up to 123 UTF-8 bytes. Works on web and desktop.
- **Ping / pong** — desktop only. **Ping** sends a Ping control frame (the chevron adds an optional payload of up to 125 bytes); the matching pong is logged as a system entry with its round-trip time, which also feeds the **Latency** stat. Pings the server sends are logged too (they are answered automatically). The browser `WebSocket` API exposes no ping/pong frames, so on web the control is disabled and the transcript can't show them.
- **permessage-deflate toggle** — desktop only. Under **Options**, turn off *Offer permessage-deflate compression* to test servers without compression; browsers always negotiate compression themselves.
- **Freeze & export the log** — freeze pauses the view while messages keep arriving (a counter shows how many are new; search and filters still apply), and export downloads the current filtered log as JSON or NDJSON (one message per line).

## Web-specific path

The browser `WebSocket` API can't set custom headers on the upgrade, and the web build currently connects directly with the browser API — so handshake headers configured in the UI are **not sent** on web (a system message in the transcript says so when it happens). A Worker relay (`/api/ws-ticket` → `/api/ws`) exists server-side to lift this limitation but is not wired into the renderer yet. Use the desktop app when the server requires upgrade headers.

## Desktop-specific path

The Electron main process opens the socket directly with the native `ws` library, so:

- Custom headers go straight on the upgrade frame — no Worker ticket needed.
- The connection is **pinned to a pre-validated IP** at connect time, closing the DNS-rebind window that pre-flight validation alone leaves open (see [ADR 0006](/architecture/adrs/0006-connection-and-dns-hardening/)).
- Redirects on the upgrade are followed.

## Tips

- Save a session: every send/receive is stored in history, replayable later.
- Use **frame assertions** (above) for per-frame checks; they run on received frames only and do not write variables back.
- For Socket.IO (which is *not* a plain WebSocket), use the [Socket.IO protocol](/protocols/socket-io/).
