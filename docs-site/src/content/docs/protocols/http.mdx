The bread and butter. Restura's HTTP client supports every method, every body shape, and gives you the full request/response timeline with timing breakdown.

## Methods

GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS, and custom methods — WebDAV (`PROPFIND`, `MKCOL`, `REPORT`), `QUERY`, cache `PURGE`, `LINK`/`UNLINK`, and so on. Open the method picker and type the method into the **Custom…** field. The desktop app, a self-hosted server, and the CLI send any custom method you type; the hosted web app supports a fixed list (see below).

Custom methods must be a valid HTTP method token (RFC 9110: letters, digits and a few symbols such as `-`, `_`, `.`, `!`, no spaces). They're sent exactly as typed, case included; the seven standard methods are always sent in upper case. Custom methods survive OpenCollection, Postman and HAR import (HAR keeps the case too) and OpenCollection and Postman export. Workflows and AI Lab accept them, and the CLI runs them. Postman stores methods in upper case, so a mixed-case custom method comes back upper-cased from a Postman round trip. OpenAPI 3.0 has no slot for custom methods, so an OpenAPI export skips those requests and warns.

**Hosted web app:** the Cloudflare Workers runtime can only send a fixed set of methods: the standard ones, `PURGE`, the WebDAV/DeltaV set (`COPY`, `LOCK`, `MKCOL`, `MOVE`, `PROPFIND`, `PROPPATCH`, `UNLOCK`, `ACL`, `REPORT`, `MKACTIVITY`, `CHECKOUT`, `MERGE`), `SEARCH`, `QUERY`, `NOTIFY`, `SUBSCRIBE`, `UNSUBSCRIBE`, `MSEARCH` and `BAN`. They go out in upper case. Any other method, `LINK` included, fails with a clear error. Use the desktop app or a self-hosted server for those.

`CONNECT`, `TRACE` and `TRACK` are always refused, whatever the casing. `CONNECT` would turn the proxy into a raw tunnel, and `TRACE` (and its IIS alias `TRACK`) echoes your request headers, credentials included, back in the response. Importing a collection that uses them falls back to `GET` and shows a warning.

## Body types

- **None**
- **JSON** — the **Beautify** button formats the body and keeps `{{variable}}` references exactly as written, including bare ones like `"id": {{id}}`.
- **Text** — plain text, UTF-8.
- **XML** — syntax highlighted; sent with `Content-Type: application/xml` unless you set your own.
- **Form data (`multipart/form-data`)** — supports file inputs.
- **Form URL-encoded (`application/x-www-form-urlencoded`)** — edit as a key/value table, or switch to **Text** to edit the encoded string directly.
- **Binary** — drag in any file; Restura reads it as a stream.
- **Protobuf** — paste base64 or upload a binary; helpful for testing gRPC-style endpoints behind a JSON adapter.

## Headers, params, cookies

- **Query parameters** — kept in sync with the URL. Type or paste `?a=1&b=2` into the URL bar and the rows appear in **Params**; edit a row and the URL updates. Disabled rows stay in the table and are left out of the URL.
- **Paste a cURL command** into the URL bar to fill in the method, URL, headers and body. A toast offers **Undo**.
- **Bulk edit** — switch params or headers to a text view with one `key: value` per line. Prefix a line with `//` to disable it.
- **Variables** — hover a `{{variable}}` in the URL or a param value to see its value and where it comes from (environment, collection, folder, globals). Secret values are masked.
- **Headers** — autocompletion for standard names + values where applicable.
- **Cookies** — per-request override, plus a session-wide cookie jar. When a response sends several `Set-Cookie` headers (a session cookie plus a CSRF token, say), every one is kept: the cookie jar stores each, the response **Headers** tab shows each on its own row, scripts see them all, and `restura run` results list them all. Streaming responses (SSE, NDJSON) have no **Headers** tab, but their cookies still reach the jar. On the web they travel in an `x-restura-set-cookies` header, so the browser never stores them for the Restura site. The network console lists each response cookie's name and attributes with the value redacted.

## Authentication

Every auth scheme Restura sends works on HTTP: Bearer, Basic, API Key, OAuth 2.0 (all four common grants with PKCE), OAuth 1.0a (HMAC-SHA1), AWS Signature v4, WSSE, and mTLS on desktop. Digest and NTLM can be configured but are not yet applied on send. See the [auth guide](/guides/auth/).

## Code generation

Click the `</>` icon next to the URL, or run **Copy as cURL** from the command palette. Snippets resolve variables from every scope and include the request's auth, including auth inherited from a folder or collection.

**Mask secrets** is on by default: secret variables stay as `{{name}}` references and credentials become placeholders such as `<token>`. Values stored in the desktop keychain are never printed. Auth that's computed per request (Digest, NTLM, AWS Signature v4, OAuth 1.0, WSSE) and binary bodies are noted as comments rather than generated. Multipart form-data is generated for cURL, Python and JavaScript. The last language you picked is remembered.

Available languages:

- `curl`.
- Python (`requests`).
- JavaScript (`fetch`).
- Node.js (`axios`).
- Go (`net/http`).
- Ruby.
- PHP.
- More languages added in releases — open an issue if your stack is missing.

## History & timing

Every send is recorded to history with status, timing, request hash, and a quick way to **resend**. Per-response, you get:

- **Status** and status text. Hover or focus the status for a plain-language explanation.
- **Timing**: the **Timeline** tab breaks the total into phases.
  - Everywhere: *Waiting* (time to response headers, including any redirects), *Download* (the body), and the remaining overhead. On the web this is the round trip to the Restura *Proxy*; on desktop it's *App* time such as scripts and IPC.
  - Desktop only: *DNS* and *Connect + TLS* are also measured for direct connections. They're left out when a proxy is used, because they would describe the connection to the proxy.
- **Size**: the decoded body size.
- **Compression**: compressed bodies are decoded before display. On desktop this covers `gzip`, `br`, `deflate` and `zstd`, including stacked codings such as `Content-Encoding: gzip, br`. If a response uses a coding the app can't decode, the raw bytes are shown with a notice above the body, and the `Content-Encoding` header is kept. The same happens when a response stacks more than three codings. The 10 MB response size limit applies to the decoded body and is checked after every decoding step. zstd bodies that need more than an 8 MB window are refused. HEAD, 204 and 304 responses and empty bodies are never decoded.
- **Headers**: filter by name or value; *Copy all* copies one `Name: value` line per value.
- **Body**:
  - pretty-printed JSON with a collapsible **Tree** view (*Copy path* gives a JSONPath you can paste into the JSONPath box)
  - syntax-highlighted XML
  - **Download**, saved under the request's name with the right extension
- **Compare with previous**: once a request has an earlier response in history, a toolbar button diffs the two side by side.
- **Cancel**: while a request runs, the response panel shows the elapsed time and a **Cancel** button. GraphQL can be cancelled too.

## Worth knowing

- The **SSRF guard** blocks requests to RFC 1918, RFC 6598 (CGNAT), link-local, loopback, IPv4-mapped IPv6, cloud metadata endpoints (`169.254.169.254`), and IPv6 unique-local — unless explicitly allowed (e.g. `ENVIRONMENT=development` in the Worker, `--allow-localhost` in the CLI).
- The **desktop client** also enforces a **pre-flight DNS guard** against DNS-rebind: hostnames are resolved before connecting, and every record is validated.
- **Custom CAs**, **disabled TLS verification**, **client certificates (mTLS)**, and **SOCKS4/5** proxies are <Badge text="desktop only" variant="caution" /> — the browser sandbox doesn't expose them.
- **HTTP version** <Badge text="desktop only" variant="caution" /> — in a request's **Settings** tab, choose *Auto* (h2 offered via ALPN over TLS, the default), *HTTP/1.1 only*, *HTTP/2 only* (the request fails if the server can't negotiate h2; on direct and SOCKS connections this is checked before anything is sent, but through an HTTP proxy (including one from `HTTP_PROXY`/`HTTPS_PROXY`) only after the response, so the request may already have gone out over HTTP/1.1), or *HTTP/2 cleartext (h2c, prior knowledge)* for `http://` servers that speak HTTP/2 without an Upgrade. The protocol actually used shows as the **HTTP** stat on the response. h2c works on direct connections and through SOCKS, but not through an HTTP proxy. On the web the runtime negotiates the protocol, so the setting stays on *Auto*. The setting is saved with the request and round-trips through OpenCollection (`x-restura-http`); importing it changes only the HTTP version, not the request's other settings. `restura run` doesn't apply it and prints a warning instead.
