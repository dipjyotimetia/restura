GraphQL in Restura is HTTP underneath, but the editor knows the spec: it can introspect the endpoint, hint completions from the schema, and run subscriptions over WebSocket (`graphql-transport-ws` or legacy Apollo `subscriptions-transport-ws`) or Server-Sent Events (`graphql-sse`).

## What works

- **Introspection** — "Refresh Schema" against any GraphQL endpoint; Restura fetches the schema and uses it for completion and validation. Runs through the shared proxy (so it carries the request's auth + TLS/proxy config and works on desktop, where a direct fetch is CSP-blocked).
- **Load a schema by hand** — for endpoints with introspection disabled. **Load** (next to the SDL download in the query toolbar, or the upload icon in the schema explorer) accepts a `.graphql` / `.graphqls` / `.gql` SDL file, pasted SDL, or an introspection JSON result (`{ "data": { "__schema": … } }` or `{ "__schema": … }`). Parse errors are shown with their line and column. The schema is saved on the request — it survives reload and travels with the request when saved to a collection or exported to OpenCollection — and drives completion, validation and the schema explorer (marked **IMPORTED**). Refresh asks before replacing an imported schema with an introspection result.
- **Query / Mutation / Subscription** — operation type detected from the document.
- **Variables** — separate JSON editor; resolves environment placeholders (`{{userId}}`).
- **`{{variables}}` in the URL** — autocompleted and highlighted (unresolved names are flagged). Resolved from the active environment and globals at send time.
- **Persisted queries** — send by hash if the server supports it.
- **Authentication** — the same auth schemes as HTTP. Most teams ship a Bearer token here.
- **Headers** — bulk edit (one `key: value` per line, `//` to disable a row) and an optional description per row; header values resolve `{{variables}}`.
- **Subscriptions** — over WebSocket (`graphql-transport-ws`, or Apollo's legacy `subscriptions-transport-ws`) or `graphql-sse`, picked per request with the **Protocol** selector in the Subscription tab (default **Auto**). Live events stream into the response panel. On desktop the socket is tunnelled over the WebSocket IPC bridge and graphql-sse over the SSE IPC handler (the packaged CSP blocks renderer `ws:`/`wss:`/`http:`), with header auth carried on the handshake.

## Subscriptions in depth

Query and mutation documents POST through the shared HTTP proxy, same as any other HTTP request. A subscription is different: Restura opens a long-lived connection using the request's **Protocol** setting (saved on the request and carried through OpenCollection export):

| Protocol | Wire | Notes |
| --- | --- | --- |
| **Auto** (default) | WebSocket | Offers both `graphql-transport-ws` and `graphql-ws` in `Sec-WebSocket-Protocol` and speaks whichever the server selects (one handshake). A server that selects none is treated as `graphql-transport-ws`. |
| `graphql-transport-ws` | WebSocket | The modern [graphql-ws](https://github.com/enisdenjo/graphql-ws/blob/master/PROTOCOL.md) protocol. |
| `subscriptions-transport-ws` | WebSocket, subprotocol `graphql-ws` | Apollo's [legacy protocol](https://github.com/apollographql/subscriptions-transport-ws/blob/master/PROTOCOL.md) (`connection_init` → `start` → `data`/`error`/`complete`, `ka` keep-alives ignored). |
| `graphql-sse` | HTTP `POST` → `text/event-stream` | [graphql-sse](https://github.com/enisdenjo/graphql-sse/blob/master/PROTOCOL.md) *distinct connections* mode only (single-connection mode isn't supported). Streams through the same path as the [SSE](/protocols/sse/) feature: the Worker proxy on web, the SSE IPC handler on desktop — so the SSRF policy applies. Request headers are sent as real HTTP headers. |

WebSocket URLs are derived from the request URL by swapping the scheme (`http(s)://` → `ws(s)://`); graphql-sse does the reverse. The negotiated protocol is shown on the **connected** line of the response panel.

- **Lifecycle** — the response panel steps through **connecting** → **connected** → a stream of **data** messages → **complete** (or **error** if the server rejects the connection or the document). A 30-second connection timeout aborts the attempt if the server never acknowledges.
- **Web** — uses the browser's native `WebSocket`. Browsers can't set custom handshake headers, so auth rides the `connection_init` payload instead (Restura's request headers become `connectionParams`).
- **Desktop** — the socket is tunnelled over the WebSocket IPC bridge, which *can* set real handshake headers, so auth is sent as actual headers on the WS upgrade request rather than (or in addition to) `connection_init`.
- **Switching operations** — selecting a different operation in a multi-operation document disconnects the previous subscription before starting the new one.

<Aside type="note">
Only header-shaped auth applies to a subscription handshake: Bearer, Basic, API Key, and OAuth 2.0 tokens. Sign-at-wire schemes — Digest, OAuth 1.0a, AWS SigV4, NTLM, WSSE — need the full request body or a challenge/response round-trip, which a WebSocket upgrade doesn't have, so they're not applied to subscriptions even if they're configured on the request.
</Aside>

## Editor features

- Syntax highlighting + bracket matching.
- Auto-format (`Cmd+Shift+F` / `Ctrl+Shift+F`).
- Inline error markers when the document doesn't validate against the schema.
- Quick switch between operations if the document defines multiple.

## Tips

- If the server gates introspection in production, use **Load** to paste the SDL or load a schema file (or an introspection JSON exported from a staging server) to keep completions and validation working.
- Subscriptions count as a long-lived response — see also [SSE](/protocols/sse/) and [WebSocket](/protocols/websocket/) for raw transport access.
- For load-style testing, drive a GraphQL collection through the [CLI](/reference/cli/) — same wire format as HTTP, JUnit / HTML / JSON reporters included.
- To try GraphQL against a real server locally, `echo-local` serves query/mutation over its HTTP endpoint (`http://localhost:8080/graphql`, POST — already in the generated collection with working auth) and a subscription endpoint over WebSocket (`ws://localhost:8085/graphql`, `subscription { tick(count) { n timestamp } }`) that you drive manually. See [Local test stack](/testing/local-stack/).
