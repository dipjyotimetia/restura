A purpose-built viewer for `text/event-stream` endpoints. Connect, watch events flow in, filter by event type, and export the log.

<TryIt protocol="sse" />

## What works

- **Connect** to any `text/event-stream` URL.
- **`{{variables}}` in the URL** — autocompleted and highlighted (unresolved names are flagged). Resolved from the active environment and globals at connect time.
- **Automatic reconnect with `Last-Event-ID` resume** — a dropped stream is reestablished after the server's `retry:` interval and sends the last-seen `id:` back as the `Last-Event-ID` header, so a well-behaved server can pick up where it left off. See [Reconnection behavior](#reconnection-behavior).
- **Per-connection event-type filter** — narrow the view to a single event name; each connection keeps its own filter.
- **Freeze & export the log** — freeze pauses the view while messages keep arriving (a counter shows how many are new; search and filters still apply), and export downloads the current filtered log as JSON or NDJSON (one message per line).
- **Long-running session** — stays open until you disconnect; capped by your platform's connection budget.
- **Resizable config pane** — with **Headers** open, headers, auth and the resume option get their own pane above the event timeline; drag the divider (or focus it and use the arrow keys) to resize. The position is remembered.
- **JSON pretty-printing** — when the event `data:` is valid JSON.
- **Custom request headers + structured auth** — Basic, Bearer, API Key, and OAuth 2.0 (API-key-in-query supported) applied at connect. Restura does **not** use the browser `EventSource` API — the stream is proxied through the Worker on web and over IPC on desktop, so custom headers and auth work on **both** platforms. (Sign-at-wire schemes — AWS SigV4 / OAuth 1.0a / WSSE — are not applied to SSE.)
- **Header table** — bulk edit (one `key: value` per line, `//` to disable a row) and an optional description per row; header values resolve `{{variables}}`.
- **Code generation** — copy the connection as browser `EventSource` (no custom headers), `fetch` + `ReadableStream` (supports headers), or `curl -N`.

## Reconnection behavior

<Aside type="note">
Reconnection is **automatic** (WHATWG §9.2.3) while **Auto-reconnect** is on (the default). Turn it off in the config pane to make the stream stop for good when it drops.
</Aside>

- When an open stream ends or errors, the status changes to **reconnecting** and Restura reconnects after the reconnection time — 1 s by default, or the server's last `retry:` value. Each attempt is logged and counted in the **Reconnect** stat.
- Reconnects send `Last-Event-ID: <last id seen>` when "Reconnect on resume" is on (default), so a spec-compliant server replays only what you missed. The same header is sent when you click **Connect** again yourself.
- The last event ID is tracked per the spec: an `id:` persists across later events until a new one arrives, a data-less heartbeat block carrying only `id:` still moves it, and an empty `id:` resets it — after which no `Last-Event-ID` header is sent.
- Restura does **not** reconnect when the server says not to: a non-2xx status, `204 No Content`, or a response whose `Content-Type` isn't `text/event-stream`. A connect that fails before the stream has ever opened isn't retried either. Network failures on a reconnect (server unreachable, or the web proxy's own `502`/`504` while the upstream restarts) are retried.
- Up to 5 consecutive reconnect attempts are made without receiving an event; after that the stream is marked disconnected. The count resets once a reconnected stream delivers an event — a server that accepts and immediately closes doesn't reconnect forever.
- Clicking **Stop** cancels any pending reconnect — a deliberate stop leaves the connection closed.
- The [CLI](/reference/cli/) captures a stream for a fixed window and does not reconnect.

## When SSE vs WebSocket

- **SSE** is one-way (server → client). Perfect for log tailing, AI streaming responses, live notifications.
- **WebSocket** is bidirectional. Use it when the client also needs to send mid-stream.
- **GraphQL subscriptions** can ride either — see [GraphQL](/protocols/graphql/).

## Gotchas

- **Line endings** — LF, CR and CRLF are all accepted, including a CRLF pair split across network packets.
- **`retry:` must be plain digits** — values like `1e3`, `0x10` or `-1` are ignored, per spec.
- **Comment lines (`: ...`) are ignored**, per spec — servers use them as heartbeats to keep intermediaries from timing out the connection. They won't show up as events.
- **Multi-line `data:` fields are joined with `\n`** before display — a server that splits one logical payload across several `data:` lines is reassembled, not shown as separate events.
- **`event:` defaults to `message`** when the server omits it — the event-type filter and timeline both use that default name.
- **Trailing data without a final blank line is dropped**, matching browser `EventSource` behavior — a stream that ends mid-event (no terminating `\n\n`) loses that last partial event.
- **Sign-at-wire auth schemes don't apply to SSE** — AWS SigV4, OAuth 1.0a, and WSSE are no-ops on this protocol; use header-based auth (Bearer, API key, Basic, OAuth 2.0) instead.

## Tips

- Many AI providers (OpenAI, Anthropic, OpenRouter) stream completions over SSE. Restura's [AI assistant](/guides/ai-assistant/) does this internally.
- Stream assertions are not available yet. In the app, SSE writes no request history and has no script hook, and the desktop collection runner skips SSE requests. The [CLI](/reference/cli/) runs SSE requests in a collection (capturing events for `--sse-duration` ms or until `--sse-events N`) and writes the captured events to the JSON report as `streamEvents`, but a test script only sees the status, headers, timing and byte count — not the events.

## Test it locally

The [local test stack](/testing/local-stack/) serves `/stream/sse` (plus `/stream/sse-named`, `/stream/sse-resume`, and `/stream/sse-comments` for exercising named events, `Last-Event-ID` resume, and comment/multi-line-data parsing) off the same `http://localhost:8080` the rest of the HTTP fixtures use — no auth required. Boot it with `npm run echo:local` (or `make echo-local`), then connect straight at it; the generated importable collection also includes a ready-to-send SSE request.
