MCP — the [Model Context Protocol](https://modelcontextprotocol.io/) — is the open standard for letting AI agents talk to tools and data sources. Restura plays both sides.

## As an MCP client

Point Restura at any MCP server and explore it like any other request target.

- **`streamable-http`** transport — the modern wire shape.
- **`http-sse`** transport — older shape; <Badge text="desktop only" variant="caution" /> the web build supports only `streamable-http`.
- **`stdio`** transport <Badge text="desktop only" variant="caution" /> — start a local MCP server (`npx`, `uvx`, `docker run`, a binary) and talk to it over stdin/stdout. See [Local servers over stdio](#local-servers-over-stdio).
- **`{{variables}}` in the URL** — autocompleted and highlighted (unresolved names are flagged). Resolved from the active environment and globals at connect time.
- **List tools** — see the server's exposed tool catalogue with schemas.
- **Invoke a tool** — fill in the JSON schema, send, watch the streamed result.
- **Result view** — Pretty / Raw / Tree, a JSONPath query, find, copy, and download for every tool result or error payload.
- **Connection headers** — bulk edit (one `key: value` per line, `//` to disable a row) and an optional description per row; values resolve `{{variables}}`.
- **List prompts / list resources** — for servers that expose them.

### Local servers over stdio

<Badge text="desktop only" variant="caution" /> Most MCP servers are local programs. Choose the **stdio** transport, enter the **command** (a name on your `PATH`, such as `npx`, or an absolute path), then open **Launch settings**:

- **Arguments** — one per line, passed to the program exactly as written. Blank lines are ignored. No shell is involved, so quotes, `$VARS`, `*` and `|` are not interpreted.
- **Working directory** — an absolute path. It defaults to your home directory.
- **Environment** — the extra variables the server needs, such as an API key. Values resolve `{{variables}}`. A variable can also come from the desktop secret store; the app resolves it when the server starts.

Connect starts the process, runs the MCP handshake, and lists the server's tools, prompts and resources, just like the HTTP transports. The server's **stderr** appears under the connection bar (the newest 64 KB; output beyond 512 KB per session is dropped), and a failed start shows the end of stderr in the error.

Arguments, the command and the working directory can't contain control characters, invisible formatting characters (such as right-to-left overrides or zero-width spaces) or line breaks. Relative command paths such as `./server` aren't accepted. On Windows, network (`\\server\share`) paths aren't accepted for the command or the working directory.

#### Consent: you approve every new command line

Starting a program is a different kind of risk from sending a request: the program runs with your user account and can read and change your files. Before Restura starts a command line it has not run before, the desktop app finds the exact program file and shows a system dialog with:

- the full path of the program (and the name you typed, if different);
- every argument;
- the working directory;
- the environment variables.

You then choose:

- **Cancel** (the default) — nothing starts.
- **Allow once** — start it this time and ask again next time.
- **Always allow** — remember this exact command line on this computer.

Any change to the program, an argument, the working directory or an environment variable (name or value) is a new command line and asks again. That includes a changed secret behind a secret-store variable.

How environment values appear in the dialog:

- Values are shown in full, except values whose name looks like a credential (for example `API_KEY` or `GITHUB_TOKEN`). Those are hidden but still count as part of the command line.
- Variables that change what runs or where it connects are always shown in full and must be plain values, not secret-store references. Examples: `PATH`, `NODE_OPTIONS`, `LD_*` / `DYLD_*`, `NPM_CONFIG_*`, `PYTHON*`, `GIT_*`, proxy and CA-bundle variables.
- Secret-store variables show the label saved with the secret.

Very long arguments or values are cut in the dialog with a "more characters not shown" note. In that case only **Allow once** is offered.

Approvals are stored by the desktop app and protected with your operating system's keychain. A collection, an imported file, or anything else in the request can't carry or pre-grant an approval: an imported stdio request still asks the first time you connect. If the keychain isn't available (for example on Linux without a keyring), Restura can't remember approvals and asks every time. **Forget approvals** under **Launch settings** clears every remembered approval.

Approving a command line doesn't vouch for the code it runs. The program file, the scripts it loads, or a downloaded package can change later. For example, `npx -y some-package` runs whatever that package publishes at the time.

#### What the process gets

- **A minimal environment, not the app's.** The server receives `PATH`, `HOME` (or the Windows equivalents such as `USERPROFILE` and `SystemRoot`), `SHELL`, `TERM`, `USER`, the temp directory and your locale settings, plus the variables you set. Tokens and credentials in Restura's own environment are not passed on.
- **No shell.** The program is started directly. On Windows, `.cmd`/`.bat` launchers such as `npx.cmd` run through `cmd.exe`, and the dialog says so. Arguments for them can't contain `"`, `%` or `!`; to pass those, start the underlying `.exe` (for example `node.exe` with the script path) instead.
- **Your secrets, if you give them.** Secret-store variables are passed to the server as plain values. A server that prints them sends them to its stderr, which Restura shows.
- **It stops when you do.** Disconnecting, closing the tab or window, or quitting Restura stops the process. If it ignores the request to exit, it is killed after one second. On Windows the whole process tree is ended. At most 8 stdio servers run at once.

:::note
On macOS, an app started from the Dock gets a short `PATH` that may not include Homebrew or nvm, so `npx` can fail with "not found". Use an absolute command path, for example `/opt/homebrew/bin/npx`, or set `PATH` in **Environment**.
:::

When you export or save a collection to files, environment values with credential-like names are written without their value, and only references to the secret store are kept.

stdio is not available in the web app, the self-hosted server, or the CLI. A saved stdio request opened there explains that it needs the desktop app, and `restura run` fails the item without starting anything. The design and its residual risks are recorded in [ADR 0030](/architecture/adrs/0030-mcp-stdio-transport/).

### Desktop protocol compatibility

The desktop app connects with the current MCP v2 client. Its automatic version negotiation supports both modern v2 servers and legacy MCP servers during the connection handshake, so saved MCP requests do not need a protocol-version setting. stdio servers are the exception: they connect with the standard `initialize` handshake, because the client's automatic negotiation would start a second, hidden copy of the server to probe it.

Legacy negotiation is handled inside the v2 client. Restura does not construct a second SDK client or retry authentication, TLS, DNS/SSRF policy, network, or timeout failures, so those errors remain visible rather than being masked by another connection attempt.

This compatibility path is desktop-only. The web and self-hosted clients retain their existing stateless Worker proxy behavior, and `http-sse` remains desktop-only.

After connecting, Restura uses the v2 client's typed operations for every standard request supported by the negotiated protocol era: ping, completion, legacy logging level, tools, prompts, resources (including subscriptions), and v2 server discovery. That preserves the client's protocol-era validation, pagination, caching, and modern HTTP behavior instead of treating a production MCP server as an untyped JSON-RPC endpoint. Non-standard server extensions remain explicit requests so their server-provided JSON-RPC errors can still be inspected.

### Modern server coverage

Restura's v2 test server exercises modern discovery alongside tools, prompts, resources, cache hints, schema-declared request headers, multi-round `input_required` responses, and change subscriptions. The MCP workspace currently presents the core catalogue and request operations; it does not yet provide dedicated UI flows for interactive `input_required` prompts or managing subscriptions.

The same URL validation, DNS pinning, header policy, and Electron IPC validation apply before the SDK is allowed to connect.

## As an MCP server

Restura can also *be* an MCP server for an agent like Claude. The server ships today but fails closed — it exposes no saved data until collection sync and consent controls land ([progress](/overview/delivery-plan/#plan-mcp-server)).

The stdio server uses the v2 server package with its built-in legacy transport compatibility, so modern and legacy clients are served without retaining the v1 SDK.

The desktop app exposes these tools:

- `list_collections` — enumerate your collections.
- `list_requests` — browse requests inside a collection (filterable by folder).
- `list_environments` — list environments and their currently active variables.
- `get_environment` — fetch one environment's details, with secrets auto-redacted.
- `get_history` — query past request executions with filters and a limit.

Every tool is **consent-gated** — each surface is hidden until you share it — and every response is **redacted** so secrets, tokens, and auth headers don't leak into agent context.

See the [MCP server mode guide](/guides/mcp-server-mode/) for setup.
