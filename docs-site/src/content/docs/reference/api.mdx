The Restura server exposes these HTTP endpoints. The same Hono app runs in the Cloudflare Worker (`api.restura.dev`) and in the Node / Docker self-hosted process.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Liveness check. Returns 200 + `{ status: 'ok', version }`. |
| `GET` | `/ready` | Readiness check. Returns `{ status: 'ready', version }`. |
| `POST` | `/api/proxy` | HTTP upstream proxy. SSRF-guarded, body normalisation, auth signing. |
| `POST` | `/api/import/fetch` | Fetch a public import artifact by URL (no custom headers/auth; private networks always refused). |
| `POST` | `/api/grpc` | gRPC unary + streaming via Connect protocol. |
| `POST` | `/api/grpc/reflection` | gRPC reflection requests. |
| `POST` | `/api/mcp` | MCP client proxy (streamable HTTP; the HTTP-SSE transport is desktop-only). |
| `POST` | `/api/telemetry/error` | Scrubbed renderer error reports (opt-out). Public — no token required. |
| `GET` | `/api/feature-flags` | Protocol kill-switch flags. Public — no token required. |
| `POST` | `/api/ws-ticket` | Mint a short-lived ticket for the WebSocket proxy. |
| `GET` | `/api/ws?ticket=<id>` | WebSocket proxy endpoint (single-use ticket, 30 s expiry). |

## Authentication

Production requires one of:

- `X-Restura-Proxy-Token: <WORKER_PROXY_TOKEN>` (or `Authorization: Bearer <WORKER_PROXY_TOKEN>`) on each request, **or**
- A valid `Cf-Access-Authenticated-User-Email` header from a trusted reverse proxy (when `REQUIRE_CF_ACCESS=true`).

With neither configured, `/api/*` fails closed with `503`. `/health`, `/ready`, `/api/feature-flags`, and `/api/telemetry/error` need no token.

Local dev bypasses auth when running under Miniflare or when `DEV_BYPASS_AUTH=true` is set in `.dev.vars`.

## Rate limiting

Cloudflare deployment: rate-limiting binding in the Worker.

Self-hosted: per-replica in-memory token bucket. For multi-replica setups, put a rate limiter in your reverse proxy.
