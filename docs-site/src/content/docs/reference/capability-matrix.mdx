Restura's capability matrix is **data-driven**: there's a single source of truth at [`src/lib/shared/capabilities.ts`](https://github.com/dipjyotimetia/restura/blob/main/src/lib/shared/capabilities.ts) and a CI gate (`npm run capabilities:check`) that fails if the published doc drifts from the code.

## Quick summary

### Available on both web and desktop

- HTTP / REST (all methods, body types).
- GraphQL — queries, mutations, subscriptions over WebSocket (`graphql-transport-ws` / legacy `subscriptions-transport-ws`) or `graphql-sse`.
- gRPC unary + server streaming (via the Connect protocol).
- WebSocket — connect, send/receive, session transcript with export (no request history).
- Server-Sent Events — basic stream viewer with reconnection.
- MCP — streamable-HTTP transport (`http-sse` is desktop-only).
- Socket.IO — emit / listen / ack.
- Collections, environments, scripts, and the safe OWS workflow profile: sequential, guarded (`if`), loop (`for`) and recovery (`try`/`catch`) controls with typed data/output, timeout/cancellation, and binding-only HTTP or GraphQL saved-request calls (GraphQL mutations need explicit approval). Other controls, event/process tasks, inline transport configuration and unsupported transports are rejected.
- Load testing — fire an HTTP request at bounded concurrency (browser caps effective concurrency ~6).
- Persistent IndexedDB storage (not encrypted at rest).
- SSRF guard on every request proxied through the Worker (HTTP, GraphQL queries and `graphql-sse`, gRPC unary and gRPC-Web server streaming, SSE, MCP). WebSocket, Socket.IO and GraphQL WebSocket subscriptions connect browser-direct, so they get an in-app check instead: loopback, private-network and cloud-metadata targets are refused unless **Allow private / internal IPs** is on, and Restura asks before sending credentials over `ws://` / `http://`. gRPC server streaming over the Connect wire protocol also connects browser-direct and gets neither check — only the browser's own rules (CORS, CSP) apply.

### Desktop only

- **Kafka** — produce / consume / SASL / TLS (needs raw TCP).
- **MQTT** — publish / subscribe / QoS / TLS / MQTT 5.0 (needs raw TCP).
- **MCP `http-sse` transport** — rejected in web mode; use `streamable-http` on web.
- **MCP `stdio` transport** — starts a local MCP server process after a per-command-line consent prompt; the web app, self-hosted server and CLI never start processes.
- **WebSocket custom handshake headers** — the browser `WebSocket` API can't set upgrade headers.
- **mTLS** client certificates.
- **SOCKS4 / SOCKS5** proxies.
- **Custom CA bundle**, disable TLS verification.
- **Pre-flight DNS guard** against DNS-rebind.
- **Filesystem-backed collections** + git operations.
- **OS keychain** storage (via `safeStorage`).
- **External cloud secret references** — auth fields can reference AWS Secrets Manager, Google Secret Manager or Azure Key Vault secrets, resolved in the main process at send time. See [Secrets & vaults](/guides/secrets/).
- **Encrypted local storage** backed by an OS-keychain-wrapped key.
- **Native shell / notifications / tray**.
- **Local mock HTTP server**.
- **Browser capture desktop bridge** — a loopback receiver for the Restura browser-capture extension. See [Browser capture](/guides/browser-capture/).
- **AI assistant** — request-aware chat (OpenAI / Anthropic / OpenRouter); Electron-first, streams over IPC. No Worker `/api/ai` route.
- **Inline AI actions** — one-click *Fix request* / *Generate tests* / *Enrich docs* from a request or response, sent through the assistant's propose-and-apply flow. See the [AI assistant](/guides/ai-assistant/).
- **`rs.vault` and `rs.judge` in scripts** — `rs.vault` is an encrypted key-value store backed by the OS keychain; `rs.judge` runs an LLM-as-judge semantic assertion. Both are desktop only. See [Scripts](/guides/scripts/).
- **AI Lab** — prompt/model testing workbench (Playground, dataset evals with deterministic + script + LLM-as-judge + tool-call + pairwise scorers, an execute-and-score `http-exec` target, model-vs-model Arena, and versioned agent suites) against local and cloud models. Needs the localhost SSRF carve-out.
- **AI Lab agent tools** — saved HTTP requests and MCP servers run through the existing execution/security boundaries; non-read requests require explicit approval. Pluggable code-sandbox contracts exist, but no sandbox provider ships yet.

## Self-hosted

Self-hosted (Docker) inherits the **web** capability profile — the SPA runs in a browser, just from your own server. Kafka, SOCKS, mTLS, etc. remain desktop-only because they require Node-level networking that the browser doesn't expose.

If you need both self-hosted *and* the desktop-only capabilities, run the desktop app locally and point it at your self-hosted gateway as a normal upstream.
