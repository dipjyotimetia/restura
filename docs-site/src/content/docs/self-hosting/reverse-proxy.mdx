When you self-host Restura, put it behind your reverse proxy of choice for TLS termination, auth (via Cloudflare Access, OIDC, etc.), and rate limiting.

The container needs the proxy to:

- Forward `/api/ws` as a **WebSocket upgrade** (don't terminate the upgrade).
- Pass through the `X-Restura-Proxy-Token` header **or**, with Cloudflare Access, the `Cf-Access-Jwt-Assertion` header.
- Not strip the `Content-Encoding` header — streaming responses (SSE, chunked) depend on it.
- **Overwrite** `True-Client-IP` with the real client address, and run the container with `TRUST_PROXY=true`. The rate limiter keys on the socket peer by default, so without `TRUST_PROXY=true` every client shares the proxy's bucket. With it, the server reads `CF-Connecting-IP`, then `True-Client-IP` (`X-Real-IP` and `X-Forwarded-For` are not used outside development), so the proxy must overwrite `True-Client-IP` and strip any client-sent `CF-Connecting-IP` — a value passed through from the client lets the client choose its own bucket.

## Example configs

<Tabs>

<TabItem label="nginx">

```nginx
server {
  listen 443 ssl http2;
  server_name restura.example.com;

  ssl_certificate     /etc/ssl/restura.crt;
  ssl_certificate_key /etc/ssl/restura.key;

  location / {
    proxy_pass http://restura:3000;
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    # Overwrites any client-sent value; requires TRUST_PROXY=true on the container
    proxy_set_header True-Client-IP    $remote_addr;
    proxy_set_header CF-Connecting-IP  "";
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # WebSocket upgrade
    proxy_set_header Upgrade    $http_upgrade;
    proxy_set_header Connection $http_connection;

    # Streaming endpoints
    proxy_buffering off;
    proxy_read_timeout 1h;
  }
}
```

</TabItem>

<TabItem label="Caddy">

```text
restura.example.com {
  reverse_proxy restura:3000 {
    transport http {
      versions h1 h2c
      keepalive 30s
    }
    header_up Host {host}
    header_up True-Client-IP {remote_host}
    header_up -CF-Connecting-IP
  }
}
```

Caddy handles WebSocket upgrades and SSE buffering correctly out of the box.

</TabItem>

<TabItem label="Traefik (Docker labels)">

```yaml
services:
  restura:
    image: ghcr.io/dipjyotimetia/restura:latest
    labels:
      - traefik.enable=true
      - traefik.http.routers.restura.rule=Host(`restura.example.com`)
      - traefik.http.routers.restura.entrypoints=websecure
      - traefik.http.routers.restura.tls=true
      - traefik.http.services.restura.loadbalancer.server.port=3000
    environment:
      WORKER_PROXY_TOKEN: ${WORKER_PROXY_TOKEN:?required}
```

## With Cloudflare Access

1. Put Cloudflare Access in front of `restura.example.com` and configure your identity provider.
2. In the Restura container, set `REQUIRE_CF_ACCESS=true`, `CF_ACCESS_TEAM_DOMAIN` (your team name) and `CF_ACCESS_AUD` (the application's AUD tag), and leave `WORKER_PROXY_TOKEN` **unset**.
3. The server verifies the signed `Cf-Access-Jwt-Assertion` on every request: signature, issuer, audience and expiry.

<Aside type="caution">
With either variable missing the server returns 503. If `WORKER_PROXY_TOKEN` is also set, the token check runs first and is the only one used. Other SSO gateways don't send this assertion: set `WORKER_PROXY_TOKEN` and have the gateway add `X-Restura-Proxy-Token` after it authenticates the user.
</Aside>

See [Self-hosting / Docker](/self-hosting/docker/) for the env var names.

## Multi-replica notes

WebSocket tickets are per-replica in-memory (v1 constraint). Either use **sticky routing** on `/api/ws-ticket` and `/api/ws` paths, or stick to a single replica.

Per-replica in-memory rate limiting means high-traffic deployments should put a rate limiter in the reverse proxy too. Forwarded client IPs only count when each replica runs with `TRUST_PROXY=true` behind a proxy that overwrites `True-Client-IP`.
