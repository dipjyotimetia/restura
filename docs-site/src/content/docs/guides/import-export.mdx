Restura imports from the major API client formats and exports to **OpenCollection** — the open, vendor-neutral collection spec — as well as Postman (v3 folder / zip, or v2.1 single file), Insomnia, and Bruno.

**Drop a file anywhere** in the window to import it: Restura detects the format (Postman, Insomnia, OpenAPI, Hoppscotch, Bruno, `.http`, HAR, OpenCollection) and opens the import review — nothing is added until you confirm. You can also pick a format and choose a file from **Import collection**.

### What doesn't survive an import

Everything dropped or approximated is reported where the importer can see it, but a few cases are lossy:

| Source | What happens |
|---|---|
| Insomnia v4 | Only HTTP/GraphQL `request` resources are read. gRPC and WebSocket requests in the export are ignored. |
| Insomnia v5 | A node without children is treated as a request, so gRPC and WebSocket requests are imported as plain HTTP requests and won't work as such. |
| Bruno `.bru` | `grpc` and `ws` request types import as HTTP requests, with a `platform-unsupported` warning naming each one. |
| Postman | Unsupported auth (hawk, jwt, edgegrid, asap, azure, sasl, akamai) becomes no auth — see [Postman import](#postman-import). |

### Desktop deep-link imports

The desktop app accepts a reviewed `restura://import` link, for example
`restura://import?url=https%3A%2F%2Fexample.com%2Fcollection.json&format=postman`.
`format` is optional and may be `postman`, `insomnia`, `openapi`,
`opencollection`, `hoppscotch`, `bruno`, or `http`.

Restura only accepts public HTTP(S) source URLs without embedded credentials.
Opening a link displays the source and format first; it does not download or
import anything until you select **Download and import**. Every redirect and
target is checked by the normal URL and DNS safety policy.

## Export

From the collection menu:

- **OpenCollection** (YAML) — the canonical export format. A single `.yml` file. See the [round-trip guarantees](/reference/opencollection/#round-trip-guarantees) for what is and isn't preserved.
- **Postman v3 (folder / zip)** — the default and recommended Postman export: Postman's current YAML folder format. See [Postman v3 export](#postman-v3-export).
- **Postman v2.1 (single file · Newman)** — one JSON file for Newman and other v2.1 tooling. See [Postman v2.1 export](#postman-v21-export).
- **Insomnia** — for sharing with Insomnia users.
- **Bruno** (`.bru` archive) — for sharing with Bruno users.

Exporting to a format that can't hold some of your requests (Postman v2.1 has no item kind for gRPC, SSE, MCP, Kafka, MQTT or WebSocket, for instance) lists what was left out in an export report, so nothing disappears silently.

On desktop you can also **Save to Files / Sync to Disk** to write the collection as an OpenCollection **directory layout** — one file per request, friendly for `git`.

In OpenCollection exports, data the OpenCollection schema has no slot for — SSE/MCP requests, gRPC schema snapshots and timeouts, the desktop HTTP version preference, and a few auth options (OAuth 1.0a `addParamsToBody`, NTLM `workstation`, WSSE `passwordType`) — is stored in `x-restura-*` entries of the root `extensions` field so it round-trips; see [Restura extensions](/reference/opencollection/#restura-extensions). Postman, Insomnia, and Bruno exports keep only what those formats can express.

## Postman import

Pick a Postman v2.0 / v2.1 JSON file, a v3 **folder** (**Import folder**), a `.zip`, or a single v3 JSON/YAML file. The version is detected automatically and every format goes through the same parser the CLI uses.

- **Import report, no silent loss.** Anything dropped or approximated is listed after import: unsupported auth, saved responses, item variables, extra events, file-body paths and similar. The raw Postman data is kept in a `_postman` sidecar in the Restura store (not in file-backed, Git-friendly collections, so it is lost when a desktop file collection is saved and reloaded; see [ADR 0034](/architecture/adrs/0034-postman-shared-parser-and-sidecar/)).
- **Auth.** OAuth 1.0a and NTLM map directly. Unsupported types (hawk, jwt, edgegrid, asap, azure, sasl, akamai) import as no auth with an `unsupported-auth` warning. The raw auth is kept in the `_postman` sidecar. v3 export restores it; v2.1 export restores only hawk and edgegrid, because jwt, asap, akamai, azure and sasl have no v2.1 type and are written as `noauth` and reported.
- **Secret variables.** v2.1 variables marked `type: "secret"` (off-schema, but Postman emits them) import value-less with a warning.
- **Environment files.** In Postman (`*.postman_environment.json`) and Hoppscotch environment files, and Bruno environments (`environments/*.bru` in a Bruno import), secret variables keep their value on desktop, like a secret you type in. In the browser (web and self-host) the value is dropped, and the import warnings list the keys to re-enter. `restura run --env` also reads a Postman environment export (and `--globals` a globals export), using the values as they are.
- **Other kinds.** v3 WebSocket and Socket.IO items import as native WebSocket / Socket.IO collection items ([#1209](https://github.com/dipjyotimetia/restura/issues/1209)); placeholder folders from older imports are upgraded automatically. LLM and data items become placeholder folders. MCP stdio items import as an empty placeholder folder named `<name> (MCP stdio, disabled)` with no request inside, so nothing can launch them. Restura keeps the program, option names and env variable names in the `_postman` sidecar, but never argument or env values; recreate the request and re-enter them before you connect. Vault (secret) variables import without a value.
- **Explicit No Auth.** When a configured auth exists above an explicit Postman `noauth`, the import report gets an `explicit-noauth` entry, so `restura run --strict-import` exits 2. Export writes an explicit `noauth` (v2.1 and v3), never inherit, and markers on ancestors survive edits to child requests.
- **Request settings.** v2.x `protocolProfileBehavior` and v3 `settings` are applied as Restura request settings: `followRedirects`, `maxRedirects`, `strictSSL`, `followOriginalHttpMethod`, `followAuthorizationHeader`, `removeRefererHeaderOnRedirect`, `disableUrlEncoding`, `disableCookies`, `protocolVersion` and TLS cipher options. Keys without a Restura equivalent (such as `disableBodyPruning`) are kept in the sidecar and reported.
- **Security downgrades** such as `strictSSL: false` are called out as warnings.
- **Descriptions and scripts.** Request and folder descriptions are kept (folder descriptions in the sidecar, for export). A disabled v2.x event is never run; it is kept for reference and exported again as disabled.
- **Other kinds, details.** gRPC and MCP descriptions are kept for export (those Restura items have no description field). MQTT 5 message properties `contentType`, `responseTopic` and `userProperties` are imported and exported; other message properties are kept and reported. Form-data part content types are kept in v2.x and v3.
- **AWS Signature.** A `sessionToken` (temporary STS credentials) is not applied by the Restura signer: the import report gets an `awsv4-options` entry, and both exports restore the token from the sidecar.
- **Limits.** Archives up to 50 MB, with per-file, total, file-count and folder-depth limits; path traversal in archives is refused.

<Aside type="caution" title="Imported No Auth and unsupported auth are not sent">
Restura's `none` auth means "inherit", so an imported "No Auth" or unsupported-auth request could otherwise pick up a parent's credentials. Restura refuses to send these instead ("Not sent: ..."): an explicit Postman `noauth` request below a configured ancestor, and any request below a folder whose auth is unsupported (hawk, jwt, and so on). The explicit `noauth` choice is remembered in the `_postman` sidecar and cuts inheritance. This applies on web, desktop and the CLI, to single send on every protocol, the collection runner (items are skipped with the reason), workflows and AI Lab tools. The Auth tab shows a "Not sent" banner. Configure the request's own auth or exclude it to send. This is an interim guard until Restura models "No Auth" natively ([#1232](https://github.com/dipjyotimetia/restura/issues/1232)).

The guard holds while the collection stays in Restura's own store (and in Postman export), but OpenCollection and git-folder saves do not preserve it until [#1232](https://github.com/dipjyotimetia/restura/issues/1232) adds an explicit no-auth to the model: they write `none` as omitted, which means inherit, so the request inherits the ancestor credential again after the round trip. Set the auth explicitly on those requests before saving to those formats.
</Aside>

## Postman v3 export

**Postman v3 (folder / zip)** writes Postman's YAML folder format.

- **Web and self-hosted:** downloads `<name>.postman-v3.zip`.
- **Desktop:** writes `<picked folder>/<name>/`. If that folder is not empty Restura asks before replacing it, and replacing removes only Postman layout files, never other files you keep there.
- **Export report.** Items v3 cannot hold are listed after export: a disabled v2.x script (v3 scripts are always active) is left out and reported as `disabled-script`; SSE requests are dropped, WSSE auth becomes no auth, secret variables are written with an empty value, Restura-only HTTP settings, GraphQL / gRPC extras, attached contract specs and folder variables are not exported, MCP Streamable HTTP is written as SSE, and some Kafka / MQTT broker options are left out.
- **Secrets** follow the include-secrets prompt below.
- **Inherited auth.** Requests that inherit their auth are exported as `inherit`, including after an import with "store secrets as handles" turned on.
- **WebSocket / Socket.IO.** Native items are exported as v3 `websocket-request` / `socket.io-request`. Restura-only options (such as subprotocols, heartbeat, namespace and transports) are listed as `websocket-extras` / `socketio-extras` in the report. Credentials in the URL, query, headers and Socket.IO handshake auth are redacted.

<Aside type="caution" title="Newman cannot run v3">
Newman cannot run v3 collections. For Newman or CI on v2.1 tooling, export **Postman v2.1**. The Restura CLI (`restura run`) runs both formats.
</Aside>

## Postman v2.1 export

**Postman v2.1 (single file · Newman)** writes one `.json` file.

- **Round trip.** The export restores the `_postman` sidecar: saved responses / examples, `protocolProfileBehavior`, extra events and unsupported auth.
- **Auth.** basic, bearer, apikey, oauth1, oauth2, digest, awsv4 and ntlm are exported. Inline auth secrets follow the include-secrets prompt below (excluded means blanked, included means written). Secret variables and keychain or other external secret handles are always exported empty.
- **Export report.** Non-HTTP items (gRPC, SSE, MCP, Kafka, MQTT, WebSocket and Socket.IO) are reported in the export report and not exported, because v2.1 has no item kinds for them. GraphQL subscriptions are HTTP requests and are exported; only the subscription setting is dropped, reported as `graphql-extras`.

## Secret redaction on export

Auth credentials are **redacted by default** in collection exports. When a collection contains inline (plaintext) auth credentials, Restura warns before exporting and you choose **Export redacted** (the default — blanks every token, password, and key while keeping the auth shape: usernames, regions, key names, scopes) or explicitly opt in to **Include secrets**. `SecretRef` handles never carry plaintext; in Insomnia and Bruno exports they become opaque `{{handle:label}}` placeholders, while both Postman formats write them empty and report them as `secret-handle`. Not covered by this prompt: Postman exports write collection variable values as they are (secret variables are always emptied), and Bruno exports include every environment in the app ([#975](https://github.com/dipjyotimetia/restura/issues/975)). When you exclude secrets, credential-named urlencoded and form-data text rows (`client_secret`, `password`, and so on) are counted by the prompt and blanked in every exporter: Postman v2.1 / v3, Insomnia, OpenCollection and Bruno, along with nested OAuth 2.0 values (`client_assertion`, `code_verifier`, `assertion`). Git-native desktop files are unchanged for now ([#1234](https://github.com/dipjyotimetia/restura/issues/1234)). Keychain handles found in sidecar auth are written empty and reported. The v2.1 export report also flags restored hidden scripts (`restored-events`) and local file paths (`restored-file-path`), because Newman may run or upload them. Always re-check an export before committing it to a public repo.

## OpenCollection — why it exists

Postman locked their format and Insomnia did too. **OpenCollection** is an open spec for API collections — see the [reference](/reference/opencollection/) — designed for portability between tools, version control, and CI.
