Restura can act as an MCP server so an agent can discover your saved requests through a curated, redacted, read-only view. The server and its safety model ship today; the step that hands it your data does not yet.

<Aside type="caution" title="Current status">
The headless server starts and answers MCP requests, but it deliberately sees **no collections, environments, or history yet** — every tool call is refused as hidden. Syncing your data to the server and a Settings screen for consent are the next milestones. Follow progress on the [delivery plan](/overview/delivery-plan/#plan-mcp-server).
</Aside>

## How it runs

The desktop app has a headless mode. Launched with `--mcp-server`, it opens no window and speaks MCP over **stdio**, so the agent starts it as a subprocess — there is no network port.

```json
{
  "mcpServers": {
    "restura": {
      "command": "/Applications/Restura.app/Contents/MacOS/Restura",
      "args": ["--mcp-server"]
    }
  }
}
```

Use the path to the Restura executable on your platform (on Windows, the installed `Restura.exe`; on Linux, the AppImage or installed binary). Logs go to stderr, which agents such as Claude Desktop capture in their own log files.

## What it exposes

| Tool | What it does |
|---|---|
| `list_collections` | Enumerate collections you have shared with the agent. |
| `list_requests` | Browse requests in a shared collection (filterable by folder). |
| `list_environments` | List shared environments. |
| `get_environment` | Fetch one environment's details — secrets redacted. |
| `get_history` | Query past request executions, if you share history. |

The tool surface is read-only and metadata-shaped: an agent can ask *what* requests exist, but cannot send them or change saved state.

## Consent and redaction

- **Everything is hidden by default.** Collections (hidden / read-only / full), environments, and history each have their own consent level, and all start hidden.
- Tool input is validated against strict schemas, and every response is deeply redacted before it leaves the process.
- Secret values stay in the desktop secret store; the same [`SecretRef`](/architecture/adrs/0007-secret-ref-pattern/) machinery that protects [auth](/guides/auth/) credentials keeps them out of tool output.

## What's next

1. Sync collections, environments, and history to the headless server.
2. A Settings screen to choose what each agent may see.
3. An optional local HTTP transport bound to `127.0.0.1` with a one-time token.
